# 22. Generate Parentheses

## Step 1

`n` 個のペアの括弧を与えられた際に、全ての well-formed な括弧の組み合わせを生成する関数を書く。

- 制約：`1 <= n <= 8`

Well-formed な括弧：両側がちゃんと揃っているということだろう。具体的にはどういうものがあるかしら？両側がくっついているもの（`()`）とネストになっているもの（`(())`）があるはず。ただこの2つのパターンは排反ではないよな。

- 全てのペアは元々は両側がくっついているものに何かしらを行ったものになるはず。両側がくっついたものを一つ生成して、それに対して 1. 隣に両側がくっついたものをもう一つくっつける、2. 外側にネストを作る、という2つの選択肢があるかな。
- でも、両側がくっついたものに対して上の 1. と 2. を考えるのだと `(()())` が出てこないかも。少し見方を変えて、広くある状態（incl. `()()`, `()`, `(()())`）に対して 1. と 2. を考える、という方法にするとよさそう。
  - 現時点での一番外側の括弧に対して 1.ないし2. を適用するイメージ。これだったらうまくいくのでは？
- イメージができるまで、10分。

実装に落としていこう。

- 木構造っぽくなるかな。答えを入れる `all_parentheses` を作って、枝の末尾に到達した時点で現時点でのペアを追加していく。
  - DFSっぽい？
- 進捗状況は `n` を減らしていくことで管理しよう。`n == 0` の時点で返す感じで。
- 枝の分岐はどういうふうに表現すれば良い？
- 30分くらい考えて進まなくなったので、答えを見る。
  - 元々の方針で書いたものは `initial_idea.cpp`。重複の管理という観点が抜けてた。さらに言えば、全部試した上で重複を除去している。重複の管理は `unordered_set` でできるから可読性はまあいいとして、計算の効率は悪そう。
  - 木構造にはなっていないな。
- あと無駄なコピーも `substr` と `+` で多い。

別の見方として、制約をベースに考える方法もある。`step1.cpp` に書いた。

- 条件として、1. `(` が最大 `n` 個まで使える、2. `)` は `(` よりも多く使えない、という2つを考える。
- この条件から、使った `(` と `)` の数をそれぞれ `n_open_used` と `n_close_used` で管理しようと考える。
- 分岐の管理は、`n_open_used < n` であれば `(` を追加でき、`n_open_used < n_close_used` であれば `)` を追加できる、という形とバックトラックを使って行う。
- 一回、終了条件のところで `std::move()` を使って `current_parenthesis` を動かそうとしてエラーになった。次の再帰呼び出しでも参照で使われるので、よくない。
- こっちの方が構造的には綺麗かな。

Python で書いている人がここまでしばしば yield というのを使っていたが見なかったことにしていた。return と違って、値を一つだけ返して一時停止し、次に呼ばれたときには続きから再開できる。

- 以下のような感じで書けるのか。

  ```python
  def generate(n, open, close, current):
    if len(current) == 2*n:
        yield current
        return

    if open < n:
        yield from generate(n, open+1, close, current + "(")

    if close < open:
        yield from generate(n, open, close+1, current + ")")
  ```

- 結果をリストに溜めず、一個ずつ返している。全ての結果を保持しないのでメモリ効率が良い。
- C++20 には `co_yield` というのがあり、似たような形で使えるそう。
  - [レファレンス](https://en.cppreference.com/w/cpp/language/coroutines.html#co_yield)
