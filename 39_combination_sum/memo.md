# 39. Combination Sum

## Step 1

`candidates` の要素から選んだ和が `target` に一致するようなユニークな（i.e., それぞれの要素を使った回数が異なるような）組み合わせを全て返す。

- 制約：`1 <= candidates.length <= 30, 2 <= candidates[i] <= 40, 1 <= target <= 40`、全ての要素は異なり、何回でも使っても良い。

まず再帰で考える。適当な要素を取り出してきてそれを `target` から引くと、その差分について同じ問題を解けば良いことになる。`target` が0になったら答えに入れればよく、負になったら次に進む。

- 同じ組み合わせをどう除外するかが難しい...。ここでちょっと手間取る。
- 最終的には `step1.cpp` のようになった。ここまで20分。
  - 最初 `all_combinations` を再帰関数の外側においていたが、答えがとんでもないことになった。問題としては、全ての再帰呼び出しにおいて `all_combinations` が共有されてしまうため、ある枝で作った組み合わせが他の枝でも混ざってしまうことがある。

外側においてやる方法を考えたところ、バックトラックに行き着いた。`backtracking.cpp`。

- `findCombinations` は `findCombination` の方が良いかも？毎回1つしか新しい組み合わせは追加されない。
- 引数が多すぎるきが...。

バックトラックにもいろいろある。自分が書いていたのは1つ目のやつかな。
> この問題ですが、基本的にはバックトラックをするわけですが、分類してみると、いくつかあるように思います。
> [A, A] まで使うことが確定していて B 以降しか使ってはいけないという状況下で、
> 
> - B を一つ使うか、C 以降しか使ってはいけないか、に分岐する。
> - B の使う数を列挙して分岐し、C 以降しか使ってはいけないに遷移する。
> - 次の1個が、B, C, D, E, F... である場合に分岐する。
>
> あたりのように思っています。とにかく、抜け漏れなく分類ができれば、いいということでしょうか。
